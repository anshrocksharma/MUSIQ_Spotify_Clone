# MUSIQ — Product Requirements Document (PRD) & Development Brief

**Project Name:** MUSIQ (A Modern Hi-Res Music Streaming Platform)  
**Target Platform:** Mobile Web / Progressive Web App (Viewport: 390px, Responsive up to Desktop 1440px)  
**Tech Stack:** React 18, Vite, Tailwind CSS, Lucide React / Heroicons, Web Audio API / Howler.js  
**Project Scope:** 1-Week Academic / College Full-Stack Capstone (4-Developer Team)  
**Document Version:** 1.0.0  

---

## 1. Executive Summary & Vision

**MUSIQ** is an original, dark-first, high-fidelity music streaming client engineered for audiophiles, late-night coders, and everyday listeners. It blends Spotify-caliber usability with an edgy, cyber-acoustic aesthetic—distinguished by deep charcoal obsidian surfaces (`#101417`), radioactive neon emerald accents (`#00F59B`), lossless audio badging, and seamless touch-driven navigation.

The core objective is to deliver an end-to-end frontend and full-stack application within a realistic 1-week timeline while maintaining production-grade UI fidelity, strict component reusability, and accessible interactive states.

## 2. Problem Statement & User Personas

### 2.1 The Problem
- Modern music applications often feel bloated with non-music media (podcasts, canvas loops, heavy social feeds), muddying audio discovery.
- College full-stack teams frequently struggle with bridging design fidelity into React components, leading to unstyled states, broken media players, and inconsistent routing.

### 2.2 Target Personas
1. **The Flow-State Coder (Ansh, 21):** Wants instantaneous music playback, ambient and lo-fi mixes, zero ads, and a distraction-free dark interface.
2. **The Hi-Res Purist (Elena, 24):** Cares deeply about audio metadata (Lossless, 24-bit/192kHz, FLAC badges), track credits, and gapless playlist queues.
3. **The Casual Mobile Listener (Jordan, 19):** Navigates primarily via mobile touchscreens; values quick-pick grids, clear empty states, and an easily expandable bottom mini-player.

## 4. Feature Specifications & Requirements

### Feature 1: Persistent Global Audio Player & Mini-Player
- **Requirement:** Audio playback must never cut off when navigating between tabs.
- **Docked State:** Height 56px, anchored directly above the 64px bottom navigation bar. Shows 40x40 thumbnail, track name, artist, play/pause toggle, and skip next. Includes a 2px emerald progress bar along the bottom border.
- **Expanded State:** Tap on mini-player expands the full-screen modal with track scrubber, volume, Dolby/Lossless indicators, output route (*AirPods Pro*), and synchronized lyrics view.

### Feature 2: Personalized Home Hub
- **Requirement:** Display dynamic greeting based on system time (*"Good morning"*, *"Good afternoon"*, *"Good evening"*).
- **Interactive Quick Picks:** 6 quick cards with 1:1 square artwork that reveal a prominent green play button on hover or touch.
- **Carousels:** CSS `overflow-x-auto snap-x` lists for *Jump Back In*, *Made For You*, and *Popular Artists*.

### Feature 3: Live Search & Category Directory
- **Requirement:** Instant debounced (300ms) query filter across song title, artist name, and album.
- **Category Tiles:** 2-column grid cards styled with vibrant angular gradients (e.g., Pop, Hip-Hop, Electronic, Bollywood, Lo-Fi, Chill).
- **Recent Searches:** Stored in browser `localStorage` with individual delete tags (`x`) and a "Clear All" action.

### Feature 4: Library Management & Liked Songs
- **Requirement:** User can filter items by *Playlists*, *Artists*, *Albums*, and *Downloaded*.
- **Liked Songs System:** Special permanent playlist card with a glowing emerald audio-wave heart. Supports batch playback and instantaneous track unliking with optimistic UI updates.

### Feature 5: Authentication & Session Resumption
- **Requirement:** Clean, frictionless Login and Signup forms.
- **Perks & Features:**
  - Password strength meter (*Lossless Ready* visual indicator).
  - Social auth buttons (*Continue with Google*, *Continue with Apple*).
  - "Resuming Session" teaser card on Login to simulate continuous cloud playback state.

### Feature 6: State Resilience (Loading & Empty States)
- **Requirement:** High-perceived performance with zero jarring content layout shifts (CLS).
- **Skeletons:** Progressive CSS shimmer gradients moving over `#181C1F` surfaces.
- **Empty States:** When a playlist or search is empty, the screen displays a friendly empty illustration with an actionable primary CTA (*"+ Create First Playlist"*) and 3 recommended starter collections.

## 8. Definition of Done (DoD) & Grading Rubric Alignment

1. **Visual Fidelity:** Matches the established dark obsidian and neon emerald design system without unstyled flash.
2. **Audio Continuity:** Audio continues playing seamlessly while switching tabs across Home, Search, Library, and Playlist views.
3. **Responsiveness:** Flawless rendering on mobile viewports (390px iPhone standard) with touch-friendly tap targets (minimum 44x44px).
4. **State Coverage:** Skeletons display during simulated latency; empty states appear when collections are cleared.
5. **Clean Codebase:** Zero console errors, fully modularized React components, and readable Tailwind utility classes.
